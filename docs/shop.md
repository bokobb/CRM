# Сайт клиентов и заказы из WhatsApp

## Сайт `/shop`

Для клиентов-дистрибьюторов, без пароля: клиент вводит номер телефона; если номер не найден — создаётся
новый клиент «Клиент <номер>». Номер запоминается в cookie, повторный вход автоматический («Сменить номер»
сбрасывает). Код — `web/ShopController.java`, шаблоны `templates/shop/`.

- **Каталог** (`/shop/products`): товары по категориям, внутри категории — по алфавиту. Цена — индивидуальная
  цена клиента. Скрытые от клиентов товары (Product.hiddenFromClients, «Скрыть от клиентов» на срок) не
  показываются и убираются из корзины. Поиск по названию.
- **«+» на карточке** открывает окно ввода количества (± по шагу: 1 шт или 0,1 для весовых), с суммой;
  если товар уже в корзине — «Сохранить». Тап по карточке — экран товара.
- **Корзина** (`/shop/catalog`): степпер, прямой ввод количества, удаление; «Оформить» создаёт заказ
  (отметка «создан клиентом» — уведомление админу), экран подтверждения.
- **История** (`/shop/orders`): по неделям, состав, возвраты по заказу; при возвратах — «возврат −X» и
  **«итого Y»** (заказ минус возвраты); «Повторить заказ» кладёт состав в корзину.

## Заказы из WhatsApp

`whatsapp-gateway/` (Node.js, библиотека Baileys) подключён к номеру компании. Входящее сообщение уходит
вебхуком на `POST /api/whatsapp/incoming` (общий секрет `WHATSAPP_WEBHOOK_SECRET`).

1. Текст разбирается парсером заказов (`crm.order-parser.engine=claude`). **Ключ Claude API не задан** —
   пока автоматический разбор выключен: сообщение попадает в «WhatsApp-заказы» (входящие), админу приходит
   уведомление с текстом, заказ оформляется вручную на экране «Уточнить заказ» (или сообщение «Игнорировать»).
2. Клиент определяется по номеру телефона. Разобранный заказ создаётся как обычный (`fromWhatsapp`).
3. После отгрузки клиенту в WhatsApp уходит PDF-накладная.

Сессия WhatsApp — `whatsapp-gateway/auth_info/` на сервере (копия в локальном бэкапе). Если сессия
слетела — Настройки › WhatsApp-сессия › новый QR и сканировать телефоном компании.

Чтобы включить автоматический разбор: дописать `CLAUDE_API_KEY=…` в `~/CRM/backend.env` на сервере и
`sudo systemctl restart crm-backend`.
