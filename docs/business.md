# Роли и бизнес-процессы

## Роли

| Роль | Кто | Меню в приложении |
|---|---|---|
| `ADMIN` | владелец | всё: дашборд, заказы, возвраты, заявки на сырьё, покупки, товары, рецепты, склад, склад сырья, клиенты, отчёты, производство, техкарта, сотрудники, долги, WhatsApp-заказы, уведомления |
| `ACCOUNTANT` | бухгалтер | то же, что админ |
| `SALES` | менеджер по продажам | дашборд, заказы, возвраты, клиенты, товары, рецепты, WhatsApp-заказы, уведомления |
| `WAREHOUSE_FG` | завсклад готовой продукции | дашборд (сборка/отгрузка + продажи), заказы, возвраты, заявки на сырьё (приёмка), склад, склад сырья, отчёты, уведомления |
| `WAREHOUSE_RAW` | завсклад сырья | дашборд (сырьё), заявки на сырьё (сборка), покупки, склад сырья, уведомления |
| `TECHNOLOGIST` | технолог | производство (бригады), техкарта, сотрудники, отчёты; ставок и зарплат не видит |

Особые права: удаление товаров и клиентов — только ADMIN (товар с историей архивируется, клиент удаляется
каскадно); отмена/удаление заявок на сырьё — только ADMIN; отмена отгруженного заказа и удаление заказов —
ADMIN/ACCOUNTANT; админ может править заказ и заявку **в любом статусе** (в 1С документ распроводится,
перезаписывается и проводится снова) и **откатывать статус заказа на шаг назад**.

## Заказы клиентов

Статусы: `NEW` «В процессе сборки» → `READY` «Готов к отгрузке» → `DELIVERED` «Отгружен» → `COMPLETED`
«Завершён»; `CANCELLED` «Отменён» (`CONFIRMED`/`IN_PRODUCTION` — наследие, в потоке не используются).

1. **Создание** — менеджер/бухгалтер/админ в приложении или вебе, клиент на сайте `/shop`, или из WhatsApp
   (см. shop.md). Цена позиции — индивидуальная цена клиента (`client_prices`, тип цен клиента в 1С), иначе
   цена товара. Сразу создаётся непроведённая «Реализация товаров и услуг» в 1С (через очередь).
2. **Сборка** — склад ГП отмечает позиции чек-листом (можно изменить количество, удалить, добавить позицию),
   «Заказ собран» → `READY`.
3. **Отгрузка** — «Отгрузил» + гос. номер ТС → `DELIVERED`: остаток склада ГП уменьшается, документ в 1С
   получает дату отгрузки и **проводится**, клиенту в WhatsApp уходит PDF-накладная.
4. **Завершение** — бухгалтер «Завершить заказ» (или «Оплачено, завершить» при долге) → `COMPLETED`;
   можно поставить «Долг» со сроком оплаты (раздел «Долги», напоминание о просроченных в 09:00).
5. **Отмена** (свайп влево) — остатки откатываются, документ в 1С распроводится (черновик). Повторный свайп
   по отменённому — удаление: документ в 1С помечается на удаление (если 1С не ответила, в CRM не удаляется).
6. **Откат статуса** (только ADMIN) — по шагу назад; откат отгрузки возвращает остаток и распроводит документ.

Заказы, заведённые бухгалтером прямо в 1С, импортируются каждые 5 минут (только сегодняшние; проведённый
документ → сразу `COMPLETED`). У импортированных CRM не трогает шапку документа, только строки «Товары».

## Возвраты испорченного товара

Создаются с нуля (не на основании заказа): клиент, позиции, причина. В 1С — «Возврат товаров от
покупателя» на склад «Испорченные товары», сразу проводится. Возврат можно закрепить за заказом того же
клиента; долгое нажатие на заказ показывает «Заказ − Возврат = Итого». На дашборде фактическая продажа =
отгружено − закреплённые возвраты.

## Производство: заявки на сырьё

Статусы заявки: `NEW` «Новая» → `COLLECTED` «Собрано» → `RECEIVED` «Оприходовано»; `CANCELLED`.

1. **Создание** — бухгалтер/админ: продукты × количество замесов, дата документа. Сырьё рассчитывается по
   рецептуре (`recipes`/`recipe_items`, рецептуры можно импортировать из спецификаций 1С).
2. **Сборка** — склад сырья выдаёт сырьё по чек-листу (можно заменить сырьё, поправить количество; при
   нехватке остаток уходит в минус) → `COLLECTED`. Правки после выдачи пишутся в историю (долгое нажатие —
   разница: зелёным «довыдать», красным «вернуть»).
3. **Оприходование** — склад ГП принимает готовую продукцию по строкам (фактическое количество) → `RECEIVED`.
   В 1С: «Отчёт производства за смену» (продукция) + «Требование-накладная» (материалы, на основании отчёта);
   отчёт проводится при оприходовании, требование — по кнопке «Завершить».
4. **Бригада** — технолог назначает сотрудников на заявку (один сотрудник — одна бригада в день).
5. **Слияние рецептур** (иконка в шапке «Заявок на сырьё») — выбрать 2+ заявки и посмотреть общую
   рецептуру: сырьё сложено, разбивка по заявкам, нехватка на общий итог. Только просмотр.

## Себестоимость

Раздел «Производство» и страницы дашборда админа «Себестоимость» / «Себестоимость продуктов».

- **Сырьё:** фактически выданное по заявкам дня, разнесённое по продуктам пропорционально норме. Цена
  сырья = последняя закупка не позже даты (иначе ближайшая после); сырьё без цены идёт как 0 ₸ и выводится
  списком «нет цены».
- **Зарплата бригады:** сумма ставок за смену (`employees.daily_rate`, иначе оклад/рабочие дни месяца).
- **Накладные цеха:** дневной фонд группы «Цех», по заявкам дня пропорционально зарплате бригад.
- Оклады групп «Продажи» и «Администрация» в себестоимость не входят.
- Себестоимость единицы — на фактически оприходованное количество; выручка — по цене продажи товара;
  наценка = (выручка − себестоимость) / себестоимость. История — 14 дней.
- **Техкарта** (меню «Техкарта», правит ADMIN): рецептура + этапы (t°, время, ККТ), органолептика, срок
  годности, хранение, упаковка.

## Закупки сырья

Закупка = поставщик (`counterparties`, загружаются из 1С или создаются вручную) + несколько позиций
(сырьё, количество, сумма) + дата + фото накладной. В 1С — «Поступление товаров и услуг» на склад
материалов. Цена из закупки становится ценой сырья для себестоимости.

## Склады

- **Склад ГП** (`products.quantity_in_stock`): приход — оприходование заявок, расход — отгрузка заказов;
  ручные поступления/списания; остатки синхронизируются из 1С каждые 5 минут.
- **Склад сырья** (`ingredients`): приход — закупки, расход — выдача по заявкам; минимальный остаток
  (`min_threshold`), ниже нормы — в «Низких остатках» и уведомление.
- Движения — `stock_movements`.

## Сотрудники и табель

Сотрудники импортируются из 1С (кнопка-облако на экране «Сотрудники»; оклады — из плановых начислений 1С)
или заводятся вручную. Группы затрат: Бригада / Цех / Продажи / Администрация. Табель ✓/✗/В по дням месяца с
выгрузкой в Excel (отчёт «Табель сотрудников»).

## Отчёты

`GET /api/reports/{key}?from&to`, один экран на все. Доступ по ролям:

| Отчёт | Ключ | ADMIN/ACCOUNTANT | WAREHOUSE_FG | TECHNOLOGIST |
|---|---|---|---|---|
| Оприход за смену | `shift-receipt` | ✓ | ✓ | ✓ |
| Табель сотрудников | `employees` | ✓ | | ✓ (без денег) |
| Клиенты: продажи и возвраты | `clients` | ✓ | ✓ | |
| Товары: продажи | `products` | ✓ | ✓ | |
| Закупки по поставщикам | `purchases` | ✓ | | |
| Сводка за период (продажи − расходы) | `summary` | ✓ | | |

Плюс «Производство: план / факт» с выгрузкой PDF.

## Дашборд (приложение)

Страницы листаются свайпом, внизу — «Новый заказ» или «Новая заявка на сырьё».

| Роль | Страницы |
|---|---|
| ADMIN | Обычный · График · Лента дня · Себестоимость · Себестоимость продуктов |
| ACCOUNTANT | Обычный · График · Лента дня · Сырьё · Сырьё · график |
| SALES | Обычный · График · Лента дня |
| WAREHOUSE_FG | Обычный (сборка/отгрузка) · Продажи · График · Лента дня |
| WAREHOUSE_RAW | Сырьё · Сырьё · график · Лента дня (без денег) |

«График» — продажи за 7 дней и «Требует внимания» (мало сырья, просроченные долги, застрявшие заказы).
«Низкие остатки» показываются только если что-то ниже нормы или в минусе.

## Уведомления

`NotificationService.notifyRole` пишет уведомление в журнал (`notifications`) и шлёт push на тему Firebase
`role_<РОЛЬ>`: новый заказ — складу ГП и бухгалтеру (админу — только если заказ создал клиент сам), собран /
отгружен / отменён — бухгалтеру и админу, низкие остатки, просроченные долги, ошибки выгрузки в 1С — админу.
