# Интеграция с 1С (1cFresh)

1С:Бухгалтерия для Казахстана в облаке 1cFresh остаётся учётной системой; CRM ведёт оперативный учёт и
приводит документы 1С к своему состоянию. Доступ — стандартный OData-интерфейс
(`<ONEC_BASE_URL>/odata/standard.odata/…`, Basic-авторизация), реквизиты в `backend.env`
(`ONEC_BASE_URL`, `ONEC_USERNAME`, `ONEC_PASSWORD`). Ключи организации, складов, счетов, типов цен —
в `application.properties` (`crm.onec.*`).

## Что CRM пишет в 1С

| Событие в CRM | Документ 1С | Когда проводится |
|---|---|---|
| Создан / изменён заказ | Реализация товаров и услуг (тип цен клиента, Комментарий «Заказ CRM №…») | при отгрузке («Отгрузил»), дата = дата отгрузки, время 07:00 |
| Отмена заказа | та же реализация | распроводится (остаётся черновиком) |
| Удаление заказа | та же реализация | распроводится и помечается на удаление |
| Заявка оприходована | Отчёт производства за смену + Требование-накладная (основание — отчёт) | отчёт — при оприходовании, требование — по «Завершить» |
| Закупка | Поступление товаров и услуг (склад материалов) | сразу |
| Возврат | Возврат товаров от покупателя (склад «Испорченные товары») | сразу |
| Правка админом после проведения | тот же документ | распровести → записать → провести снова; при ошибке старая версия проводится обратно |

Проведение — только операцией OData `/Post` (`PostingModeOperational=false`, чтобы проходили документы
прошлой датой). `PATCH {"Posted": true}` движений не создаёт — не использовать.

## Что CRM читает из 1С

| Что | Как часто |
|---|---|
| Остатки склада ГП и сырья | каждые 5 минут (`crm.onec.sync-cron`) |
| Реализации, заведённые бухгалтером (→ заказы), поступления (→ закупки) | каждые 5 минут с 7 до 18 |
| Возвраты | каждые 5 минут |
| Контрагенты, типы цен клиентов, индивидуальные цены | по кнопке (привязка клиента, «Синхронизировать цены») |
| Рецептуры (спецификации), сотрудники, оклады, подразделения | по кнопке |

## Фоновая очередь

CRM не ждёт 1cFresh: изменённая запись помечается `onec_pending = true`, после коммита один поток
`onec-queue` вызывает `reconcile(id)` нужного `OneC*SyncService`. Ошибка не мешает работе — текст
сохраняется в поле `onec_sync_error` записи и уходит уведомлением админу; при недоступности 1С (Fresh
отвечает 301 на страницу `/availability`) — автоповтор каждые 10 минут. Синхронными остались только
удаления (если 1С не ответила — запись в CRM не удаляется).

## Правила, о которых важно помнить

- Клиент должен быть привязан к контрагенту 1С (`clients.oneccontragent_key`), иначе заказ не выгрузится.
- Индивидуальный прайс клиента — «Тип цен номенклатуры» с именем клиента (не договор). Новый тип цен
  заводится в 1С документом «Установка цен номенклатуры».
- Номенклатура сопоставляется с товаром по ключу (`onecnomenclature_key`), иначе по названию.
- Неотгруженный заказ ⇔ черновик в 1С; отгруженный ⇔ проведён.
- Документы, помеченные на удаление, не импортируются обратно.
- 1cFresh иногда закрывает запись (301 на `/availability`) при работающем чтении — ждать, очередь повторит сама.
